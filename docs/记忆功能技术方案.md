# 「记忆」功能技术方案

> 版本：v2.2（2026-10-07，对齐原型最新调整：多图、位置、横屏、缩放、上传页改版、播放手势）
> 范围：小程序「记忆」Tab（官方精选内容展示 / 上传投稿 / 沉浸式预览）+ 内容审核（管理员人工审核、官方账号发布）
> 关联原型：`prototype/龙城小程序.pen`（记忆 Tab 列、我的 Tab · 内容审核行）

---

## 1. 需求概述

### 1.1 功能范围

| 模块 | 内容 |
| --- | --- |
| 记忆 Tab | 替换原「工具」Tab，双列瀑布流展示**官方已发布**的图片/视频，上下滑动浏览 |
| 上传投稿 | 「记忆投稿」表单页：上传**最多 10 张图片或 1 个视频**（互斥），可选关联活动、可选位置、可选备注（50 字），提交即进入审核队列；图片逐张过微信官方图片审核（上传预审） |
| 预览 | 图片/视频全屏沉浸式预览；**多图上下滑动切换**；图片双指缩放（放大态仅保留「还原适宽」）；视频自动播放（静音起播），支持暂停、拖动进度条、**横屏播放（含快进/快退拖动态与播放手势）** |
| 内容审核（管理员） | 管理员在「我的 · 内容审核」中预览投稿（视频卡/图片卡）并通过/不通过；**通过即以官方账号身份发布**；横屏查看态无裁决按钮 |

### 1.2 核心规则（定稿）

1. **记忆 Tab 只展示 `published` 内容**：审核中、未通过的内容对**所有普通用户（含上传者本人）均不可见**。
2. **上传即投稿**：用户上传后直接返回成功提示，没有"私有相册"、没有"我的投稿"状态页。
3. **发布主体唯一**：公开内容 100% 由官方账号发布（PGC），平台对公开内容承担主体责任；小程序为内部人员使用，审核结果**线下交流**，不做线上通知。
4. **审核分工**：图片上传预审走微信官方接口（`imgSecCheck`，决定"能不能进审核队列"）；公开与否一律由管理员人工决定。
5. **媒体形态**：一条记忆 = 1 个视频 **或** 1~10 张图片；多图在预览中**上下滑动切换**（无翻页指示器）。

## 3. 数据模型

### 3.1 `memories` 表（新增）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 自增主键 |
| user_id | BIGINT FK → users.id | 投稿人（原作者） |
| activity_id | BIGINT FK → activities.id **NULL** | 关联活动（**非必填**，空则不展示活动行） |
| media_type | VARCHAR(8) | `image`（多图）/ `video`（单视频） |
| duration_ms | INT NULL | 视频时长（仅 video） |
| file_size | BIGINT | 文件总大小（字节，多图为合计） |
| caption | VARCHAR(**50**) | 备注（非必填，≤50 字，过 msgSecCheck） |
| location_name | VARCHAR(128) NULL | 位置名称（**非必填**，如"龙城桌游馆（东门店）"） |
| location_lat / location_lng | DECIMAL NULL | 位置坐标（选填，POI 选择时带回） |
| status | VARCHAR(16) | `pending` / `published` / `rejected` / `offline`，默认 `pending`；索引 `ix_memories_status_created (status, created_at)` |
| reject_reason | VARCHAR(500) NULL | 未通过原因（留痕与线下沟通） |
| publisher_id | BIGINT FK → users.id NULL | 发布操作的管理员 |
| published_at | DATETIME NULL | 发布时间 |
| source_credit | TINYINT(1) | 发布时是否署名原作者 |
| created_at / updated_at | DATETIME | 常规时间戳，索引 `ix_memories_user` |

### 3.2 `memory_media` 表（新增，媒体明细）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| memory_id | BIGINT FK → memories.id | 所属记忆，索引 |
| sort | TINYINT | 图片顺序（1~10）；video 恒为 1 |
| file_path | VARCHAR(512) | 存储相对路径 |
| thumb_path | VARCHAR(512) | 缩略版路径（瀑布流/列表用） |
| cover_path | VARCHAR(512) NULL | 视频封面帧（仅 video） |

### 3.3 `memory_audit_logs` 表（不变）

`submit` / `api_reject` / `manual_publish` / `manual_reject` / `offline` 全量留痕。

### 3.4 状态机（不变）

```
图片（逐张 imgSecCheck 预审）/ 视频 ──▶ pending
pending ──(管理员 通过)──▶ published    pending ──(不通过)──▶ rejected
published ──(下线)──▶ offline
```

可见性：`published` 全员可见；其余仅管理员可见（含投稿人本人不可见）。

## 4. 上传投稿流程（「记忆投稿」页）

### 4.1 页面结构（原型已定稿，两态：未完成 / 已完成）

- 标题栏：无标题（仅返回 + 胶囊菜单）；页面内居中标题「记忆投稿」+ 副标题。
- 表单卡片组（字段组样式，Label 14/700 + 灰底槽 r:16 #F3F4F6，参照新建活动）：
  1. **上传内容**（必填）：缩略图九宫格（94×94 r:12）+「+ 添加」占位格；
  2. **位置**（非必填）：选择槽 → 拉起 `wx.chooseLocation`，带回地点名与坐标；
  3. **关联活动**（非必填）：选择槽 → 活动选择器，展示「活动名 + YYYY/M/D 周X HH:mm」；
  4. **备注**（非必填）：多行槽，上限 **50 字**（≈3 行），右下字数计数 `0/50`。
- 底部：主按钮「上传」（342×56 r:28 橙色，与新建活动「下一步」同规格），按钮贴 Touch Bar 上方。

### 4.2 客户端流程

1. `wx.chooseMedia`：图片模式 `count: 10`（多选 ≤10）；视频模式单选，`maxDuration: 180`；视频 >20MB 先 `wx.compressVideo`。
2. 选位置（可选）：`wx.chooseLocation` 带回 `name/address/latitude/longitude`。
3. `wx.uploadFile` 提交 `POST /v1/memories`（multipart）：`files[]`（图片多张 / 视频单条）、`cover`（视频封面帧）、`activity_id?`、`location_name?`、`location_lat?`、`location_lng?`、`caption?`、`duration_ms?`。
4. 服务端：图片**逐张** `imgSecCheck`（任一不过 → 整体拒收 422）；视频直接入库 `pending`；备注过 `msgSecCheck`。
5. 成功回执：`wx.showToast`「已提交，审核通过后将由官方发布」→ 返回记忆 Tab。待审内容对本人同样不可见。

### 4.3 服务端上传校验

| 项 | 规则 |
| --- | --- |
| 图片 | jpg/jpeg/png/webp，单张 ≤ 10MB，**1~10 张** |
| 视频 | mp4，≤ 100MB（建议压缩后 ≤ 50MB），时长 ≤ 180s |
| 图片分辨率 | 单边 ≤ 4096；视频 ≤ 1080p |
| caption | ≤ **50** 字 + `msgSecCheck`（可空） |
| location | 名称 ≤ 128 字（可空） |

## 5. 审核与发布流程

### 5.1 图片官方预审（上传门槛，逐张）

- `security.imgSecCheck` 逐张同步检测；任一 `87014` → 整体拒收，toast 通用违规提示；
- 调用失败/限流 → 放行入库标记 `pending`（日志记 api_error），不阻塞投稿。

### 5.2 管理员人工审核与官方发布

审核列表卡片双形态：

| 视频卡 | 图片卡 |
| --- | --- |
| 封面 + 左上播放标识 + 时长 | 封面（无播放标识）+ **「图片 · N 张」**（无时长） |
| 大小（hard-drive 图标） | 大小（hard-drive 图标） |
| 活动名（截断） | 活动名（截断） |

审核预览：

- **视频竖屏**：信息组 + 进度条 + 通过/不通过 + 上传人栏右侧**横屏入口**（maximize-2）；
- **视频横屏**：全屏播放控制（中央播放钮 + 进度条 + 退出横屏），**无通过/不通过**——退出横屏回竖屏页才能裁决；
- **图片**：上下滑动切换多张，无进度条；双指放大后进入纯查看态（隐藏信息组与裁决按钮，仅「还原适宽」，还原后才能继续操作）；
- 通过 = 官方账号发布（可署名「来自 @xxx 的投稿」）；不通过 = 退回，结果线下告知。

## 6. 接口设计汇总（v1）

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/v1/memories` | 上传投稿（multipart：files[]、cover?、activity_id?、location_*?、caption?、duration_ms?） | 登录用户 |
| GET | `/v1/memories` | 瀑布流分页（cursor；**仅 published**） | 公开 |
| GET | `/v1/memories/{id}` | 详情（仅 published；含 media 列表按 sort 排序、location_name） | 公开 |
| GET | `/v1/admin/memories` | 审核队列（status/media_type/分页） | admin |
| GET | `/v1/admin/memories/{id}` | 审核详情 | admin |
| POST | `/v1/admin/memories/{id}/review` | publish / reject / offline | admin |
| GET | `/v1/admin/memories/pending-count` | 待审核角标数 | admin |

公开列表 item 增加：`media: [{url, thumb_url}]`（多图数组）、`location_name`；不返回投稿人 id/头像（仅 `source_credit.nickname` 字符串）。

## 7. 小程序端改造

### 7.1 Tab 改造（不变）

`tabBar.list[1]`：工具 → 记忆；原工具页迁移到「我的」页设置菜单。

### 7.2 记忆瀑布流页（不变 + 多图封面）

- 双列瀑布流 + cursor 分页；视频卡封面帧 + 播放标识；**多图卡取第 1 张作封面**；
- Wi-Fi 下首个可视视频卡片静音起播。

### 7.3 预览页（按原型定稿更新）

- **多图**：全屏单图展示，**上下滑动切换**上/下一张（页面右缘上下箭头，40×40 半透底）；无张数指示器；
- **图片缩放**：双指放大后进入纯查看态——隐藏底部信息组与切换箭头，仅显示「还原适宽」按钮（110×32 半透明黑胶囊，距底部 24，minimize-2 + 文案）；点击还原 1:1 后才能继续翻页；
- **视频**：自动播放（静音起播）；底部进度条可拖动；上传人栏右侧横屏入口；
- **横屏播放**：844×390 全屏，顶部仅返回键（无标题），底部进度条（当前时间/总时长）+ 退出横屏（minimize-2）；
- 底部信息组：官方账号、备注（展开/收起）、`📍 位置名`（有位置时）、`⚑ 活动名 ｜ YYYY/M/D HH:mm`；间距 8+16、行高 120%、进度条到底部边距 24。

#### 7.3.1 视频播放手势规范（竖屏预览与横屏播放一致）

| 手势 | 行为 |
| --- | --- |
| **单击屏幕** | 切换控制层（顶部栏/底部信息组/进度条）显示与隐藏；控制层显示后 **3 秒无操作自动隐藏** |
| **屏幕内左滑** | **快进**：沿进度向前拖动，显示快进指示胶囊（⏩ + 目标时间/总时长）、进度条出现拖头圆点与精确时间气泡，松手后从目标时间起播 |
| **屏幕内右滑** | **快退**：沿进度向后拖动，显示快退指示胶囊（⏪ + 目标时间/总时长），其余同上 |
| **双击屏幕** | **暂停 / 继续**；暂停时画面中央出现 play 三角钮，播放中中央无任何 icon |

播放状态 icon 规则：**播放中中央无 icon；暂停时中央显示 64×64 半透圆 + play 播放钮**。

### 7.4 记忆投稿页（全新改版，见 §4.1）

### 7.5 内容审核页（管理员）

待审核列表（视频卡/图片卡）、视频竖屏审核预览、视频横屏播放（播放中/暂停/拖动快进/拖动快退）、图片审核预览、图片放大态、备注展开态、空状态。

## 8. 存储与媒体处理

1. `storage/memories/<yyyy>/<mm>/<uuid>.<ext>`；`MEMORIES_CDN_BASE_URL` 前缀切换 CDN；
2. 图片每张生成展示版（最长边 1600，q85）与缩略版（最长边 800）；
3. 视频客户端压缩为主；封面帧用 `thumbTempFilePath`；
4. `rejected` 满 30 天、`offline` 满 90 天清理（媒体文件随 memory_media 级联）。

---

## 9. 安全、合规与风控（不变）

PGC 口径提审；admin 路由 `require_admin`；上传按用户限流（20 条/日）；`memory_audit_logs` 全量留痕；普通用户不可见投稿人身份细节；公开内容保留举报入口。若 UGC 类目放开或主体升级，可平滑切换"用户直发"模式。

---

## 10. 性能与体验指标（不变）

瀑布流首屏 < 1.5s；起播 < 800ms（Wi-Fi）；审核列表 < 1s；图片预审 < 3s/张（多图并行送检）。

## 11. 分阶段实施计划

**P0 · 基础链路（1 周）**
1. Alembic 迁移：`memories` + `memory_media` + `memory_audit_logs`；
2. `memory_service`：投稿（多图/单视频）/列表（仅 published）/详情 + imgSecCheck（逐张）+ msgSecCheck；
3. 小程序：记忆 Tab（瀑布流）、**记忆投稿页（新表单：位置/非必填/50 字）**、预览页（图片多图上下滑 + 视频）；
4. pytest：模型、上传校验（含 10 张上限、50 字上限）、状态机、可见性矩阵。

**P1 · 人工审核与发布（1 周）**
1. admin 审核接口（publish/reject/offline）+ 角标；
2. 小程序：我的·管理员入口、审核页（视频卡/图片卡、竖屏/横屏/图片预览/放大态）、发布署名；
3. 视频自动播放 + **横屏播放（含播放手势：单击显隐/双击暂停/左右滑快进快退）**；图片双指缩放 + 还原适宽；
4. 端到端联调：投稿→审核→官方发布→瀑布流可见。

**P2 · 体验与上线准备（1 周）**
1. CDN 前缀接入 + 图片双版本清单；
2. 限流、清理脚本、监控打点（投稿量/审核时延/发布量/驳回率/多图占比）；
3. 提审口径材料（PGC 说明、征集流程说明、举报入口）；
4. 按《正常发版-发布前清单》走查发布。

## 12. 风险与开放问题

1. **UGC 类目政策变动**：按 PGC 口径上线；政策放开或主体升级后切换"用户直发"。
2. **线下通知遗漏**：未通过原因靠线下告知，审核页提供「复制原因」便于粘贴到微信群。
3. **视频不引 ffmpeg**：客户端上报时长/封面以管理员预览校验为准。
4. **多图流量**：10 张图单条上限约 100MB 原始流量，靠客户端压缩与缩略版控制展示成本。
5. **Tab 切换灰度**：工具页迁移到「我的」页的时机与产品确认，必要时双入口并存一周。
