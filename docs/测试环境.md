# 测试环境统一规范

## 日常联调

唯一逻辑：小程序 -> 本地 FastAPI -> 服务器测试 MySQL；头像、分享图、记忆图片和视频写入同一服务器的测试媒体目录。手机与开发者工具只是访问本地 API 的地址不同，数据库和存储不变。

- 数据库：服务器 `dragon_reserve_test`，禁止连接正式库 `dragon_reserve`。
- 文件：服务器 `/home/ubuntu/apps/dragonReserveSystem-test/data/storage` 与 `data/memories`，禁止使用正式服务的目录。Windows 中的 `R:` 是 SSHFS 网络挂载，不是本地文件副本。
- API 调用使用本机地址，媒体 URL 使用服务器测试 API 的既有 HTTPS 地址。图片/视频可直接从服务器读取，避免客户端再经本地挂载绕行；待审媒体的签名和账号权限由同一测试库及测试密钥校验。
- 服务器已有测试记忆 worker；日常启动不重复启动 worker，不运行迁移、造数、清空或同步数据。
- 本地可以保留源代码、配置、日志、操作系统/播放器的临时缓冲；不能另建持久业务数据库或把已上传素材保存在本机目录作为唯一来源。
- SSHFS 仅使用 1 秒的内存目录元数据缓存并同步写入服务器，不开启本地磁盘镜像；服务器 worker 新生成的文件最多需等短暂元数据刷新。挂载跨网络，不代表与服务器本地磁盘有相同延迟。
- 文件清理必须等待实际删除及容量账本提交，小程序仅对确认删除接口使用 120 秒等待时间；普通读取/审核仍保持原请求时限，不用成功提示掩盖未完成的删除。超时后先刷新服务器实际状态，不盲目重复操作。

## 入口与依赖

统一实现为 `backend/scripts/test_environment.py`。PowerShell 与 Bash 只是参数转发入口，不再分别实现数据库、配置或存储逻辑。旧 `start_backend_local_phone.ps1`、`init_local_phone_db.py` 已移除；`.tmp/` 的历史脚本不能作为环境入口。

依赖本机后端虚拟环境、OpenSSH、已验证的服务器 SSH 主机密钥与登录密钥，以及本机 FFmpeg/FFprobe（API 上传校验使用，压缩仍交服务器现有 worker）。Windows 安装 [WinFsp 与 SSHFS-Win](https://github.com/winfsp/sshfs-win)；Linux/macOS 安装对应 SSHFS。启动脚本不自动安装系统驱动，不关闭主机密钥验证。若二进制不在 PATH，可在本机 `.env.test` 显式指定 `MEMORY_FFMPEG`/`MEMORY_FFPROBE`，不能照搬服务器的 `/usr/bin` 路径。

按 `backend/.env.test.example` 配置被 Git 忽略的 `.env.test`。启动时通过已认证 SSH 读取服务器正在运行的测试 API 配置，核验测试库和媒体目录，只在本次进程中复用测试 JWT、邀请码、微信凭据和媒体签名，不复制 `.env` 文件到本机、不生成新密钥、不读取正式环境的配置。`TEST_MEDIA_MOUNT` 在 Windows 使用空闲盘符（默认 `R:/`），Linux/macOS 使用空目录。环境文件中的旧 `MYSQL_HOST/PORT` 不再决定实际数据库端点。

```powershell
cd backend
# 只验证远端 MySQL、媒体写入/服务器哈希/删除；不启动 API、不改小程序配置
.\scripts\start_backend_test.ps1 -CheckOnly
# 开发者工具
.\scripts\start_backend_test.ps1
# 手机和电脑在互通 Wi-Fi；替换为本机实际 LAN IPv4
.\scripts\start_backend_test.ps1 -AppHost 0.0.0.0 -MiniProgramHost 192.168.10.2 -AppPort 8002
# 停止当前受管会话（后台运行时也可用，不连接数据库或新建挂载）
.\scripts\start_backend_test.ps1 -Stop
```

```bash
cd backend
bash scripts/start_backend_test.sh --check-only
bash scripts/start_backend_test.sh
bash scripts/start_backend_test.sh --stop
# 手机：先设置本机实际 IP，勿开放到公网
APP_HOST=0.0.0.0 MINI_PROGRAM_HOST=192.168.10.2 APP_PORT=8002 bash scripts/start_backend_test.sh
```

启动使用新建、独占的 SSH 隧道，而不是看到本地 3307 可连就认作远端。只读核验实际数据库名称，通过挂载写入随机小探针，在服务器校验哈希，再删除并确认不存在；校验成功后才切换小程序配置和启动 API。配置中的数据库密码不输出到日志。端口、数据库、SSH 或挂载失败均停止，不回退 SQLite/本地 MySQL/本地目录。

保持启动终端打开，以 Ctrl+C 结束。先停止本地 API，再恢复小程序正式 HTTPS 模板、卸载本会话挂载并关闭本会话隧道；不停止别人的会话。配置在运行期间被人工改动时不覆盖。强制杀进程/断电不保证清理：先检查残留进程、盘符和 `backend/storage/test-environment.lock`，确认无运行实例再处理，不直接删除锁去启动第二套。

本地 HTTP/IP 仅用于可信局域网调试，不做路由器端口转发，不上传发布该配置。普通扫码预览、电脑微信和手机微信的 HTTPS/合法域名限制需分别验收，挂载成功不代表客户端网络连通。

## 允许的例外

1. `pytest tests` 的隔离自动化测试：`tests/conftest.py` 显式设置 `ALLOW_LOCAL_TEST_DATABASE=true`，使用临时 SQLite 与合成数据/临时媒体，不连接共享库，不供小程序登录联调，不代表 MySQL 验收。这个开关不得写入日常 `.env.test`。
2. 迁移回归：CI 的一次性 MySQL，或显式指定的专用迁移测试服务；使用随机 `migration_test_*` 库并清理，不对共享测试库执行破坏性回归。
3. 其他离线复现：必须先获得明确授权并限定数据、范围和清理方式，不能默认新增本地业务库。应用不再提供默认 SQLite URL；缺少数据库配置直接报错。

自动化回归中的本地临时数据是刻意隔离的例外，不是“本地测试环境”的另一种运行方式。

## 历史数据与审计

历史 README 曾推荐手机专用 SQLite，记忆调试也曾使用 `.tmp/memory-local.db`。这些是旧实施记录，不再是当前规范。已有文件不自动删除、导入或覆盖服务器测试数据；需先确认是否有待保留内容，再单独迁移或清理。本轮不执行任何正式环境发版或正式数据操作。
