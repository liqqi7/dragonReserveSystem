# 3.2 新增范围与实施顺序

更新：2026-09-13。来源为用户从侧边对话明确同步的需求，已经授权实施，不作为待确认建议。本文覆盖旧文档中将成本、标签、完整记分纸等排到二期的条目；`implementation-status.md` 记录实际完成情况。

页面范围最新修正：本轮同时实现真实微信小程序页面及接口接线，基于已合入的原型和现有组件，让核心流程可用；静态原型和流程说明仅作设计辅助，不代替业务页面。不得将全部原生页面联调推到后续。自动化联调与开发者工具/真机渲染分开记录。

## 明确排除

- 不开发图片上传、挑战/目标管理（包括 10×10 和年度目标）。普通次数统计和 H-index 保留。
- 不开发用户数据导出、对局/记分纸导出、依赖导出文件的分享，以及 BGG 或其他平台回写。
- AI/OCR、翻译、分类机制中英文映射仍不在本轮。
- 不连接生产、不导入真实用户数据、不自动公开历史。用户授权的是开发受控操作能力。

## 新增验收项

| 编号 | 本轮必须支持 | 验收边界 |
| --- | --- | --- |
| E01 | 只指定赢家；同分手动决胜 | 可不填分数/全部名次；保留结果来源与更正原因；分数、名次、结果自洽；摆烂仍计已知未获胜 |
| E02 | 通用普通/轮次记分纸与自动回填 | 累计总分、最佳一轮、赢得轮数、仅记分；安全四则/括号并保留输入；单选、勾选、辅助项、重复行和小计；缺失/0/负数、重算和版本冲突 |
| E03 | 可查询与选用的版本化模板 | 游戏、扩展组合、变体、人数匹配；选用后记录定义快照；新版本不改旧局；不做任意规则引擎 |
| E04 | 总轮数与可恢复计时 | 独立 round_count；开始、暂停、继续、结束和恢复状态；并发重复操作不重复累加 |
| E05 | 非玩家/非人类身份 | 人类玩家、automa、讲解员、主持人区分；明确实际人数、胜负与人类榜样本；日常人类仍用小程序用户 |
| E06 | 统计排除入口 | 普通录局可受控设置全部或结果统计排除；保留可读记录与原因；所有统计共用口径 |
| E07 | 详细结果和分项分析 | 当前/最长连胜、先手/新手胜率、同分/决胜次数、轮数、分差、胜者均分、最高落败分、得分曲线、角色/变体组合、按胜负的分项；样本和缺失值、钻取 |
| E08 | 个人收藏偏好 | 个人评分、愿望单、预订、长期想玩和笔记；独立于实物状态/活动提名；拥有未玩、玩过未拥有和覆盖率 |
| E09 | 成本统计 | 实物购入价格/币种；每局、每小时、人均；多盒/多币种、本人或他人实物和时长缺失口径明确 |
| E10 | 标签和组合筛选 | 个人标签、保存筛选、排除条件；人数、时长、复杂度筛游戏；标签不会替代 BGG 分类中英映射 |
| E11 | 无明细既往游玩 | 独立记录“玩过”/约 N 次；不虚构日期、玩家或完整对局；不进入月份/活动/胜率分母 |
| E12 | 持续导入与完整语义 | 稳定数据集/映射复用；同来源复用/改动确认；跨来源同局关联；团队/合作、轮数、变体、时间、备注、计算与计分表有明确投影和未知状态 |
| E13 | 导入核对与历史开放机制 | 跨来源查重、映射版本读取、差异/冲突、报告、跨任务恢复与并发幂等；核对后受控发布 held；开发不自动发布用户记录 |
| E14 | 其他入站来源与离线补传 | 核实 BGA/Yucata 实际可用接入；提供可验证适配与能力状态，缺官方能力/账号则记录阻塞；小程序离线修改按版本冲突同步，不静默覆盖 |
| E15 | 微信小程序真实页面和接口联调 | 桌游库/详情/扩展、库存/偏好/成本、活动提名/计划、选人/录局/成绩/记分纸/计时、历史/统计/筛选钻取、标签和导入核对；加载/空态/错误/保存反馈/权限；按真实测试结果报告可用性 |
| E16 | 补齐缺失原型并交付查看 | 在既有原型与组件规范上补充实际功能所需页面、弹层和状态；整体画布及关键流程自检后交付查看，不能用“功能优先”取消原型补充 |

## 数据和接口增量方向

3.1 的 26 表为已实现基线。扩展迁移单独承载新增能力，保留原迁移的可复核基线。0014增量已经实现，合计34张领域表；以下内容已落入当前模型，业务库尚未应用迁移。

- 对局增加结果来源、手动决胜标记、总轮数、计时状态与累计秒数；现有 stats_exclusion 增加受控输入及原因。
- 人类玩家与 automa 保存在实际玩家集合；讲解员/主持人另存辅助参与关系，避免混入现有玩家聚合。
- 记分纸定义增加计算方法、行类型/选项/重复/小计语义、表达式原输入和自动回填策略。模板版本定义不可变，选择时保存快照。
- 每用户每游戏一份偏好及既往游玩信息；标签、关联、保存筛选各自保存。价格属于实物，汇总不隐式换汇。
- 离线变更存稳定客户端操作 ID、输入哈希与结果，复用资源 revision 和现有权限；冲突返回服务端当前版本。
- 导入保持私有原件，新增预览、映射读取、报告及有审计的发布操作；外部入站只按官方实际能力实现。

## 实施顺序与状态

1. 范围和来源能力已核对；BGA/Yucata直连的外部条件尚未满足，接口如实返回能力状态。
2. 录局基础：E01、E04–E06；再实现依赖这些字段的 E02、E03。
3. 收藏与筛选：E08–E11；随后以统一筛选和计分口径实现 E07、E09。
4. 来源与恢复：E12–E14；更新跨对话导入运行说明，补合成样例与冲突回归。
5. 各模块同步贯通 E15 的真实小程序页面，维护实际接口契约、迁移/回滚说明；执行 SQLite 全量回归、隔离 MySQL 及前后端流程验收。E16已新增独立补全画布和交互预览，主画布保持既有合入内容。

外部能力核验依据为 BG Stats 的 [记分纸](https://www.bgstatsapp.com/score-sheets/)、[详细统计](https://www.bgstatsapp.com/explanations/game-page-stats-segment/)、[非玩家](https://www.bgstatsapp.com/explanations/non-players/)、[成本](https://www.bgstatsapp.com/explanations/cost-per-play/) 与 [同步说明](https://www.bgstatsapp.com/cloud-sync-info/)。链接是核验入口，尚未核验的第三方接入不能记为已实现。

当前实现、设备边界与验收结果以 [实施记录](implementation-status.md)、[验证报告](verification.md) 和 [当前契约](12-v3.2-implementation-contract.md) 为准，不再使用以上实施顺序作为未完成状态。
