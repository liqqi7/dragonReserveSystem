# v3.2 基础实施契约

更新：2026-09-13。本文与运行代码、[生成的 OpenAPI](openapi.json)、[逐列数据字典](database-columns.md)、[参考 DDL](database-schema.sql) 一致。03/06/08/09 保留 v3.1 的方案推导与样例；有差异时以本文和当前请求模型为准。当前统计定义版本为 `5`，来源解析版本为 `3`。

v3.3 名称搜索与选版录入增量见 [14 名称录入](14-name-intake.md)，运行 OpenAPI 和字典已同步0015及新增路由。本文继续记录未变更的基础业务契约。

## 1. 身份、权限和事务

- 原生录局 `players[].user_id` 从小程序用户列表选择，服务在同一事务映射到唯一 `Person`。持久参局外键仍是 `person_id`。导入接口可使用尚未绑定账号的私有 Person；不按姓名自动绑定账号。
- 人类玩家、automa 分别为 `participant_kind=human/automa`。automa 必须使用本局匿名身份，参与游戏内胜负，不能进入人类玩家榜。`observers[]` 记录 `teacher/moderator`，不计实际玩家人数、胜率和人次成本。
- 普通活动参与者须有有效签到才能新建该活动的对局，可以替别桌记录，不要求记录人参局。创建者及管理员按现有管理权限操作；更正权限由详情 `can_edit` 给出。现有提前签到规则不变。
- 公开业务集合为 `publication_status=published` 的可读记录；草稿按管理/创建权限读取，held 仅通过发起人的私有任务入口。其他管理员不能读取用户的原件、任务或私有映射。
- 写事务先锁当前账号，再锁聚合和来源身份，检查权限、`expected_revision` 与完整目标集合。创建请求用 UUID `Idempotency-Key`；同键不同正文返回冲突。计分表、玩家、队伍及最终成绩原子更新。
- API 基路径 `/api/v1`，复用 Bearer JWT。普通 JSON 512 KiB；文件 20 MiB。列表使用不透明游标，不能跨筛选复用游标。分数/成本用十进制字符串输出，NULL 与 0 区分。

## 2. 对局和成绩

`PlayCreate/PlayPatch` 新增或开放：`result_source`、`result_reason`、`tiebreak_applied`、`round_count`、`stats_exclusion`、`exclusion_reason`、`observers`。支持 individual、team、cooperative、solo、unscored；具体枚举和组合校验见 OpenAPI 与 `boardgame_results.py`。

| 状态 | score | 结果及统计 |
| --- | --- | --- |
| recorded | 可为 0、负数、小数 | 按有效规则判定，计数值样本 |
| unrecorded | NULL | 保留参局；不能推断为 0 分或自动判负 |
| gave_up | NULL | 保留参局，已知未获胜，进入个人有效结果分母 |
| unfinished | NULL | 个人结果未知，不自动计负 |
| table_flip | NULL | 个人结果未知，不自动计负 |

个人状态优先于队伍/共享胜利，摆烂的人不能被选为赢家。整局未完成是 `status=abandoned` 加 `end_reason`，不进入完成局榜及结果分母。作废保留审计，恢复需版本与原因。`stats_exclusion=all` 排除统计；`wins` 保留普通次数，排除结果统计；必须保存原因。

`result_source=manual_winner` 可只确认赢家，无须编造全体分数/名次；手动结果及更正保留原因。`tiebreak` 只允许最高/最低有效同分主体中的决胜，不允许跳过实际领先者。来源结果冲突、全员未赢而没有赢家证据等情况保持未知并提示核对。

| 接口 | 用途 |
| --- | --- |
| POST `/boardgame-plays/result-preview` | 服务器校验结果、自洽性和统计资格 |
| POST `/boardgame-plays/duplicate-preview` | 查相似记录，不能自动合并同天同游戏的两局 |
| POST `/boardgame-plays`；PATCH `/{id}` | 新建/更正，完整明细集合保留稳定行 ID |
| POST `/{id}/complete`、`abandon`、`void`、`restore`、`copy` | 状态变更/复制草稿，均在 boardgame-plays 下 |
| POST `/boardgame-plays/{id}/timer` | start/pause/resume/stop，带 expected_revision |
| GET `/boardgame-plays/{id}/history`；POST `/{id}/reports` | 更正历史、成员报告问题 |

计时器保存 `timer_status`、`timer_elapsed_seconds`、`timer_resumed_at`、`timer_stopped_at`。重复/并发操作不能重复累加；读取返回累计状态供恢复；结束时与时长同步。离线队列不接受计时操作，避免客户端时钟漂移制造时长。

## 3. 普通及轮次记分纸

原始导入结构 v1 保留；本轮通用输入定义为 v2，支持 number/radio/check/choice/text/subtotal、重复项及辅助项。算式只允许数值、四则、括号和一元正负，限制长度、深度、精度及除零；保存原输入和计算结果，不执行来源 JavaScript、函数或任意表达式。

计算方式为累计总分、最佳一轮、赢得轮数、仅记分。辅助项不加分；小计依赖须无环；重复行按稳定 base_key 供统计聚合。未知输入不作 0；赢得轮数须所有有效主体所需轮次齐全才能计算。个人特殊状态不被计算回填覆盖。

| 接口 | 约定 |
| --- | --- |
| GET/PUT/DELETE `/boardgame-plays/{id}/scoresheet` | play_revision 与 sheet_revision 双版本，定义/单元格/成绩一起核对 |
| POST `/boardgame-plays/{id}/scoresheet/preview` | 计算预览，不落库 |
| GET `/boardgame-score-templates` | 游戏、扩展、变体、人数过滤 |
| GET `/boardgame-score-templates/{id}`；POST `/boardgame-score-templates` | 读取定义；创建独立版本 |
| POST `/boardgame-plays/{id}/scoresheet/from-template` | 套用版本快照；不让模板后续修改改写旧局 |
| POST `/boardgame-plays/{id}/scoresheet/review-template` | 对来源结构进行审核，审核后才可跨局比较 |

模板 `template_family+version_number` 形成版本族；同族新版本不修改旧定义。变更参局者、队伍或规则导致现有单元格失效时，明确替换或清除计分纸，409 时保留客户端内容供核对。

## 4. 统计口径、字段及钻取

所有统计共享 `PlayQuery`：scope、活动集合、month/quarter/year/custom、来源、环境、玩家组合、扩展组合、地点、角色、先手、初玩、标签、排除游戏/玩家/地点/标签、结果、规则与计分结构。先手/初玩/角色过滤既约束局集合，也约束计分主体，避免混入同局其他玩家。

返回 `definition_version=5`、筛选回显、时间边界、指标有效/缺失样本与钻取条件；匿名历史不强行并为一个人。全体/我的都支持。胜率按同游戏/比赛模式和可比规则集合比较，一局有效结果即可入榜，不计算跨游戏 Elo。

| 接口族 | 可展示内容 |
| --- | --- |
| GET `/boardgame-stats/overview` | 完成局、游戏、时长、游玩日、人数、H-index 与模式样本 |
| GET `/boardgame-stats/wanted`、`wanted/{game_id}/sources` | 跨场累计提名人次、活动数、我的提名及来源活动 |
| GET `/boardgame-stats/most-played`、`trends`、`breakdowns` | 玩得最多、日期/活动趋势、星期/人数/环境分布 |
| GET `/boardgame-stats/players`、`partners`、`locations`、`expansions` | 玩家、伙伴、地点与实际使用扩展 |
| GET `/boardgame-stats/games/{id}/comparison-groups`、`players` | 可比规则组、单款成绩榜及结果分母 |
| GET `/boardgame-stats/games/{id}/detailed` | 胜率、先手/初玩、平局/决胜、轮数、分差、胜者均分、最高落败分 |
| GET `/boardgame-stats/games/{id}/streaks` | 当前/最长连胜，保留胜负完整顺序；拒绝先过滤掉输局的 result_filter |
| GET `/boardgame-stats/games/{id}/score-curve`、`variants`、`roles` | 得分曲线、玩法/角色组合和逐局钻取 |
| GET `/boardgame-stats/games/{id}/scoresheet-groups`、`scoresheets` | 已审核结构、分项数值/缺失样本与按胜负比较 |

个人计分按玩家，团队计分按队伍，共享计分按局统计数值样本，不能把一份共享分数复制为多份分数样本；成员结果仍按人计算。分差在同局完整结果单位间计算。数值缺失、未绑定“我”、样本为空返回明确空态/NULL。真实大规模数据性能尚未验收。

## 5. 收藏、成本与个人筛选

| 接口 | 业务 |
| --- | --- |
| GET/PUT `/boardgames/{id}/my-preference` | rating 1–10、wishlist、preordered、want_to_play、note |
| GET/PUT `/boardgames/{id}/my-prior-plays` | played_before、approximate_count、note，不虚构对局 |
| GET `/boardgame-collection/overview` | 拥有未玩、玩过未拥有、拥有游戏的游玩覆盖率 |
| GET `/boardgame-collection/costs` | 本人实物成本，按币种和盒子分别计算、可钻取使用记录 |
| GET/POST `/boardgame-tags`；PATCH `/{id}` | 私有标签、改名、归档/恢复 |
| GET/PUT `/boardgame-tags/{kind}/{identity}` | game/play 标签集合，以 expected_hash 防并发覆盖 |
| GET/POST `/boardgame-saved-filters`；PATCH/DELETE `/{id}` | games/plays/statistics 组合筛选，按账户私有 |

实物新增 `purchase_price+purchase_currency`，必须同时有值或同时为空；0 元有效，不换汇。成本分母只计算明确使用该盒的有效完成局，分别提供局数、已知时长、人次；未指定实物的同游戏对局不会摊到每盒。缺时长不计小时分母，缺价格不当免费。收藏偏好和无明细既往游玩只用于个人收藏范围，不进入月份/活动次数、胜率或明细局成本。

## 6. 持续导入、版本差异与发布

完整操作顺序见 [持续导入说明](../../boardgame-import-runbook.md)。BGG 保存完整 XML、无损节点树、参数、哈希和版本；BG Stats 保存文件及完整条目，未知字段保留。分类/机制先保存原来源，不做中英文映射。

- 数据集隔离到发起人、归属和来源；BG Stats 字典优先以 UUID 标识，RefId 只定位文件内对象。缺 UUID 时以文件哈希隔离引用，不把新文件里的同编号或同名人自动继承为旧人。BGG 玩家只复用已确认的账号身份；只有显示名时逐条核对。
- 同来源 UUID/来源键重复应用复用同一 play_id；同来源内容变更返回 source_changed。更新 held 必须指定目标版本、原因，存在计分纸时明确确认替换。跨来源同局经候选核对后 link_play；同游戏同日只是提示，不是唯一键。
- `GET /boardgame-imports/{job_id}/items/{item_id}/preview` 返回上次来源与新来源差异、locally_modified、同源关联、候选及当前可读对局。当前对局详情是本地值；不是把不同结构字段伪装为完整自动三方合并。
- `GET .../{job_id}/mappings`、`.../mappings/{mapping_id}/history` 返回确认映射及版本历史。`GET .../{job_id}/report` 返回状态/错误、application_outcomes 新增/复用/关联/更新/跳过和 publication_counts；“applied”不等于新增。操作数按来源项计，业务数量按结果 ID；跨项共享同一 ID 不等于新增多条物理记录。
- `POST .../{job_id}/publish` 要求 job/play 版本、review_token、公开确认、原因；尚有未绑定玩家时另需明确确认。事务重新校验映射和结果；并发变化返回409。重复任务也能继续核对其复用的历史，不改写原始来源溯源。
- 来源 `quantity>1` 必须提交逐局确认的 segments，不能把合并总分复制成多局。来源删除标记不删本地记录。

来源适配边界：支持已验证的团队/合作结果、时间/时区、备注、变体、轮数、实物价格、数值和安全算式；BG Stats v1 已知个人数值/文本记分结构可投影。未知规则、复杂来源模板或不明确团队语义保留原结构并进入人工核对；可用明确 `decision.play` 更正业务投影，不宣称兼容所有 BG Stats 版本和模板。

## 7. 离线补传与外部能力

`POST /boardgame-sync`：`{client_id, operations:[{operation_id, action, resource_id, payload}]}`，每批最多20项。支持 play.create/play.patch/scoresheet.put/preference.put/prior.put/inventory.patch/game_tags.put/play_tags.put。每项独立事务；稳定操作 UUID 与内容哈希保证重试复用；409 返回当前服务器版本，不能自动覆盖。

小程序队列按账号隔离，最多80项/1 MiB；记录本地草稿及冲突，查看服务器记录后选择保留或重新提交。缓存持久化依赖微信本地存储，不是跨设备云备份。

`GET /boardgame-imports/capabilities` 真实报告开关及适配状态。BGA/Yucata 暂未核实可用的官方外部对局历史接口及账号条件，返回 unavailable 和原因；不把游戏平台开发接口冒充历史 API。本轮已提供能力状态与离线补传，不包含未经验证的平台直连。

测试方法和设备限制见 [验证报告](verification.md)；真实页面见 [小程序页面清单](10-mini-program-pages.md)，原型见 [原型说明](../../../prototype/boardgame-library/README.md)。当前工作区开发完成不等于已部署：先备份、在目标 MySQL 版本试迁移、部署兼容后端和 worker，再逐步打开开关。关闭入口/worker 可停止新写入；有业务数据时保留新表，不直接降级删除。
