# BG Stats 真实导出验证与适配补充

验证日期：2026-09-11；属于 [完整技术方案](../../boardgame-library-technical-solution.md)。本轮读取用户提供的 BGStatsExport.json，验证真实格式并改进离线探针；没有导入项目业务数据库、绑定本地账号或发布历史。

本文件保留 v2.1 首次格式核验记录。v3.0 已将相应展示统计字段、接口与新表正式纳入 [08 扩展契约](08-bgstats-statistics-coverage.md)，当前验证结果见 verification；来源可读不等于业务接口已实现。

仓库内仅保留字段规则、汇总发现和完全虚构的回归样例；用户原件不复制为测试 fixture，不写入玩家姓名、地点、评论或价格明细。完整来源仍保留在用户上传的文件中。

## 2. 必须处理的实际格式

### 2.1 匿名玩家按本局出现位置区分

players[].isAnonymous=true 的目录项是占位，能够被同局多位匿名玩家引用。旧基础探针将所有重复 playerRefId 一律拒绝，真实文件在两局触发了误判。

修正规则：具名来源玩家重复引用仍拒绝；匿名占位允许重复，每条 playerScores 行产生独立 guest_key，计入各自实际参局。使用父对局来源身份、source_slot 和可用的 scoreUuid 构造本局身份；相同文件重试稳定，不把匿名占位映射成一个全局真实玩家。没有 scoreUuid 时保留源数组顺序，不能按空名/同名合并。

数据库已有 `(play_id,guest_key)` 唯一键，能容纳这一情况，无需增加表。导入 decision 与 mapping_snapshot 增加 source_slot/source_score_uuid，匿名占位不能仅凭 playerRefId 绑定本地用户，也不写入全局玩家映射。

### 2.2 嵌套扩展不生成额外对局

真实字段为 plays[].expansionPlays:[{gameRefId,bggId}]。45 条 gameRefId 全部有效，无重复或自身扩展；这批嵌套项的 bggId 都是 0。

通过 gameRefId 取对应游戏的 games[].bggId，生成主局的 boardgame_play_expansions。嵌套项的 bggId 不能替代游戏 ID，0 不能建立外部 BGG 对局关联；不能把 215 个主局加成 260 局。未知扩展字段继续留在原件。

### 2.3 空值与占位值

| 实际值 | 数量 | 规范化 |
| --- | --- | --- |
| durationMin=0 | 153 局 | 时长未知，写 NULL；另外 62 局保留实际正时长 |
| score 是正常数字字符串 | 514 行 | 按 Decimal 保存，其中 45 个 0 分有效 |
| score="null" | 31 行 | 未记录分数，写 NULL；不是字符串成绩或 0 分 |
| score="" | 17 行 | 未记录分数，写 NULL |
| rank=0 | 113 行 | 未记录名次，写 NULL |
| seatOrder 缺失 / 为 0 | 295 / 267 行 | 按源数组生成稳定展示序号，保留原字段；不能声称恢复了实际座次 |
| team="0" 且 usesTeams=false | 68 行 | 不创建队伍；原值留存 |
| 玩家 metaData="" | 2 行 | 没有附加元数据；不是整个文件的 JSON 解析失败 |

当前文件所有 usesTeams 均为 false，没有真实团队对局样本，不能因为存在 team 字符串就声称已验证团队适配。旧 scoringSetting 出现 0/1/9，另有 125 局缺失；数值语义尚未完整核实，不硬编码解释为比赛模式或计分方向。

### 2.4 计分表和元数据是 JSON 字符串

scoresheet、metaData、playImages 是外层 JSON 中的字符串。解析器只做 JSON 解码，保留原字符串及全部未知字段，不执行计算表达式。空字符串按缺失处理；格式未知/解码失败应列该项问题，原件仍保留。

计分表存在两种结构：18 局用 groups[].rows[].scores，2 局用 rounds[].rows[].scores；scores 对象的键为玩家得分记录的 UUID，通过 playerScores[].metaData.scoreUuid 关联。该文件 375 个分项键全部匹配；20 局的 62 个最终总分都是正常数字字符串。

一期保留模板、分组/轮次、变体、分项和最终总分；普通对局可采用来源已记录总分，不按未知计分表规则重新计算或覆盖来源成绩。375 项关联成功只证明关联结构可读，不代表所有计分公式/模板或小程序计分表 UI 已实现。

### 2.5 胜者、名次和未知结果

- 29 局没有明确 winner，其中 16 局有名次。可保留名次，结果保持 unknown，不能仅按 rank=1 补造胜场；这不等同于 16 局错误数据。
- 1 局名次只填写了一部分，但有多个赢家；保留原值并列为结果待核对。
- 1 局有明确的赢家与名次不一致；不得悄悄选择某一字段覆盖另一字段，导入预览提示冲突。
- 其余多赢家情况按已确认的并列/平局规则核对，不把 winner=false 默认理解为“整个游戏失败”。

这些问题不妨碍原件和 held 草稿入库，是否具备 completed/resolved 条件仍须走统一完整性校验。对局导入成功不等于可进入胜率榜；本期所有外部历史仍 held。

### 2.6 来源范围、图片和收藏

isOnlinePlay=1 保留为明确线上来源标记，缺失为未知；不能为线上或其他历史补造本地活动/报名/打卡。所有 215 条主局都带正数、互不重复的 plays[].bggId，但与 BGG 账号下同局的外部关联仍按来源账号和实际接口证据确认，不能和 games[].bggId 混用。

copies[].metaData 含购入/数量/价格/内部备注等字段，完整保留但不通过公开 DTO 暴露。本次验证的是历史对局导入，收藏信息不自动覆盖现有库存或所有者。deletedObjects 不触发任何本地删除或级联，来源变化由差异预览处理。

playImages 中的引用只保留，不抓取外链或读取文件中指定的本机路径。图片本体需要单独的图像备份验证，不宣称 6 局图片已经迁移。
