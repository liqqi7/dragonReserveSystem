## 方法与验收

[联调脚本](../../scripts/verify_boardgame_live.py) 启动实际 Uvicorn HTTP 服务和独立 worker，使用应用的 `SessionLocal`，按普通登录接口签发临时用户令牌。[录入控制器脚本](../../../miniprogram/tests/integration/boardgameEntryLiveFlow.cjs) 执行真实页面控制器、服务层和 `request.js`，仅将微信网络适配为本机 HTTP；保留实际认证头、请求超时和幂等键。BGG HTTP 未使用 mock。

验收条件：名称查询返回真实候选；worker 取得完整 Thing 和版本；确认前目录无新增；用户选版确认后保存原始来源、版次和实物；重复请求不增盒；封面 HTTPS 实际可读。BG Stats 原件与 BGG 账号历史另走当前生产适配器只读解析，只输出汇总，不应用导入任务。

## 联调发现与修复

真实 HTTP 服务的会话配置是 `autoflush=False`。录入服务创建作品后补写 BGG 原始 XML、哈希和同步信息，再创建实物；创建实物会加锁重新读取作品，覆盖尚未刷入数据库的补写字段，导致界面显示成功但部分来源元数据未落库。

修复在 [录入服务](../../app/services/boardgame_intake.py) 中把来源字段先 `flush`，然后创建实物，仍处于同一原子事务。测试会话及 worker 测试工厂现与正式配置一致；回归测试先复现 `bgg_raw_xml is None`，修复后重新加载对象核对完整来源，真实 BGG 联调也重新通过。

| 修复后回归 | 结果 |
| --- | --- |
| 全部后端 | 118 passed，28 warnings，57.69 秒 |
| 隔离 MySQL | 69 passed，7 warnings，41.62 秒；完整迁移、空业务回退重升、有版次数据降级保护均通过；实例已停止删除 |

## 复现与剩余边界

从项目根使用后端虚拟环境运行；`--bgstats-export` 是可选的只读文件参数，路径由操作者提供，禁止把用户文件提交为测试样例。

```sh
backend/.venv/bin/python backend/scripts/verify_boardgame_live.py --query 'Ark Nova' --bgg-username liqqi
```

脚本是显式运行的联网检查，不加入日常离线 pytest。图片 HTTP 成功不等于微信域名配置、真机渲染或国内弱网通过；本体原图约 1.9 MB，真实设备验收时需观察加载表现。BG Stats 人员匹配、真实导入/发布、目标环境部署和 OCR 仍未执行。修复未增加接口或迁移；部署时包含录入服务修复即可，回滚沿用关闭入口/worker并保留领域表的方案。
