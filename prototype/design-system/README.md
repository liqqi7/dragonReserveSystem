# 龙城小程序统一设计规范

生效版本：2026-09-13。依据本轮用户上传的《龙城小程序.pen》“设计规范”节点 `lnq9c`，替代此前补全原型中的蓝色主题及白底无关闭信息抽屉规则。

- [规范来源快照](source-20260913.json)：保留附件的规范节点、来源文件名与 SHA-256，不含文件访问令牌。
- [统一设计值](tokens.json)：补全原型生成器和交互预览直接读取；也是后续小程序共享样式的取值依据。
- [桌游设计对比](boardgame-comparison.md)：附件和当前实现的差异、采用范围。
- [现有小程序 UI 参照](miniprogram-ui-reference.md)：每类桌游页面对应的现有页面、构图与交互复用要求，以及尚未完成的页面调整。
- [补全原型](../boardgame-library/桌游库-功能补全.pen)：这些规则应用后的活动、录局等页面。

原附件包含多个探索稿，不能把每个探索稿的局部样式都升级为全局规范。本轮按“明确的规范说明 + 已复用的正式组件”整理规则；以下冲突处理有明确记录。仓库原有总画布保留原样，后续继续编辑时以本目录为现行规范，避免覆盖附件与本地各自保留的业务方案。

本轮更新范围为规范、项目协作规则、补全 Pencil 画布和交互预览。小程序现有页面代码仍有旧视觉取值，尚未按这份新规范完成整套界面还原；不将原型更新等同于真机界面验收。

桌游页面以现有龙城小程序的正式设计为 UI 基准，同时复用页面构图、封面卡、头像名单、分组表单和导航习惯；BG Stats 提供对局与统计能力的参考。具体安排见上述 UI 参照，不能仅替换颜色就视为已完成统一。

## 基础规范

| 项目 | 统一规则 |
| --- | --- |
| 主色 | `#FF9800`；用于主按钮、选中及关键强调，普通内容区不大面积铺橙色 |
| 辅助强调 | `#FFF3E0`、`#FFE0B2`；深色辅助文字使用来源色卡中的 `#7C3A05` |
| 文字 | 正文/标题 `#111827`，次级信息 `#4B5563`，占位/禁用 `#9CA3AF` |
| 表面 | 页面与内容卡 `#FFFFFF`；表单、一级抽屉和次级容器 `#F5F5F5` |
| 字号 | 仅使用 10、12、14、16、20、24、32 px；不沿用补全稿中的 13、15、18 px |
| 标题层级 | 一级页面标题 24/34，主要分区与二级页面标题 20/28；标题字重 700 |
| 正文 | 14/22，辅助 12/18，微型信息 10/14；16/24 用于需要更明显层级的组件文字 |
| 圆角 | 标签 8、控件/小卡 12、标准卡片 16、大容器及抽屉顶部 24 px |
| 间距 | 优先 4、8、12、16、20、24、32 px；页面边距 16、卡片间距 12；表单抽屉保留 18 px 专用内边距 |
| 阴影 | S0 无阴影；S1 控件 0/2/10、黑色约 8%；S2 卡片 0/6/20、约 10%；S3 浮层 0/10/28、约 15%；不叠加多套投影 |

原型以 390×844 px 为基准。页面尺寸、坐标、字号、实际行高使用整数；`.pen` 中行高倍率可以是小数，但相乘后的实际行高应落在规范值。小程序使用 `750/390` 转换为 rpx，生成值的小数不属于原型尺寸违规。

## 通用组件

### 导航、切换和操作栏

- 一级页面导航高 88 px，无返回按钮；标题 24 px。二级页面导航同高，含返回入口，标题 20 px。
- 微信胶囊沿用系统 black/white 逻辑；深色主视觉使用白色图标，中性透明黑底，不加品牌色或背景模糊。
- 双项分段切换高 40 px、灰底 R12、内边距/间距 4 px，标签 14 px；文字 Tab 采用两项等分及文字下方选中线。
- 小程序一级导航使用首页、日程、工具、排行、我的五项，不把“桌游库/对局/统计”演示导航升级为全局底部导航。
- 有明确提交操作时使用 80 px 白色底部功能栏，按钮高 44 px、R12；无操作的详情页不补空白底板。系统安全区由现有导航或操作栏负责，不重复累计。

### 一级抽屉

依据正式组件 `y8ZQV` 及规则 `Fabvl`、`X62Cwk`、`Waj1W`，参与人、普通信息、新建和编辑共用一级抽屉外壳。

- 灰底 `#F5F5F5`，白色内容模块，顶部圆角 24 px，底部对齐，全屏 40% 黑色遮罩。
- 顶部结构：8 px 留白 + 12 px 拖拽区 + 8 px 间距 + 40 px 标题区 + 8 px 间距，共 76 px。
- 拖拽条 38×4 px、`#9CA3AF`；标题 20 px，右侧 32×32 px 关闭入口。只显示主标题及必要数量或状态，不增加副标题。
- 高度限定为低 360 / 标准 558 / 高 720 px，对应 y=484/286/124。普通信息的内容视窗分别为 284/482/644 px；超出时滚动内容，或升级一档。
- 信息抽屉水平边距 16 px；表单抽屉 18 px。表单如有保存操作，再从内容视窗扣除 80 px 固定底栏；普通信息不增加空操作栏。
- 小程序按当前可用视口适配三档高度，最高不越过屏幕；键盘和真机安全区仍需设备验证。

### 独立 Picker 与表单

- 日期/时间/日期时间 Picker 使用独立白底组件，标准高 396 px、顶部 R24，标题栏 56 px、左右 20 px、关闭区域 32×32 px；无拖拽条，固定 80 px 确认栏。
- 选中行灰底 `#F5F5F5`、R12；叠加在表单上时保留下层状态并增加第二层遮罩。
- 输入卡白底 R12，标签 12 px，内容 14 px；Textarea 随输入增高，最多 5 行，再在内部滚动。
- 现有附件没有明确沉淀的居中风险确认模板；新增此类需求先补齐统一组件。

## 桌游业务组件

- 馆藏双列卡片标准 173×230 px、R16，页面左右 16 px、横纵间距 12 px。
- 标题单行省略；图片占剩余高度，白色信息区按内容适配。人数、时长和标签使用规范字号，不以 7–9 px 微小文字强行塞入。
- 最长验收数据：10–12 人、100–120 分钟、四个四字标签。放不下时增加信息行或将标签分两行，保留卡片总高度，由封面让出空间。
- BGG 难度：有效值低于 2.5 为轻度，2.5 至小于 3.5 为中度，3.5 及以上为重度；缺失或 0 表示暂无数据，不误判为轻度。
- 分类和机制原始数据继续存储，一期不因原型中的中文标签示例启用自动翻译；OCR 仍为二期。
- 活动提名、对局、计分和统计继续使用已确认的业务规则；视觉统一不改变比分或排名计算。

## 来源中的冲突处理

1. `Ukkyj` 残留“信息展示抽屉底色 #FFFFFF”，但 `y8ZQV` 正式组件和新增规则均为灰底；采用灰底及关闭入口。
2. 字号规范仅允许七档，但 `wg9gj` 卡片仍有 7/8/9 px，`blTaB` 有 13 px；采用七档字号，用换行/省略与内容布局解决空间问题。
3. 旧项目说明中的 Picker R22 与附件正式组件 `klCrN` 的 R24 冲突；采用 R24。
4. “布局不使用小数”指实际像素，不能据此删除 24/34 等合法的行高倍率，也不能把 rpx 转换截成错误尺寸。

## 维护与验收

组件一级分类固定为基础规范、通用组件、业务组件；同一二级分类只承担同一类职责。新增规则先并入已有分类。

更新顺序：规范与 tokens → 共享组件 → 页面引用 → 全画布及代表页面检查。必须核对所有顶层坐标/边界、模块排列、空档和碰撞，以及引用完整性、实际行高、文字溢出、遮罩、抽屉内容视窗与底栏。浏览器同源预览验证和 Pencil/微信真机验证应分别报告。
