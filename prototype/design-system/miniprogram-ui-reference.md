# 桌游页面沿用现有小程序的设计方案

更新：2026-09-13。用户要求桌游 UI 参考现有小程序。此文把页面结构、组件和交互的复用关系固定下来，与 [统一设计值](tokens.json) 一起作为桌游页面的设计与实现依据。

本次核对了用户上传的《龙城小程序.pen》正式页面，以及本地首页、工具、活动详情、排行、我的、底部导航和表单组件代码。本轮已据此调整桌游小程序代码的共享样式与页面结构，完成本地控制器联调和浏览器布局检查。补全原型保留此前交付内容，本次未修改.pen；微信设备验收单独记录。

## 采用顺序

1. 色彩、字号、间距、圆角和弹层尺寸使用 [现行统一规范](README.md)。现有代码中的旧蓝色、非规范字号、近似灰色不作为新页面取值来源。
2. 页面构图优先沿用附件正式页面：封面与标题关系、信息分组、头像名单、排行结构、表单与操作栏。现有小程序代码用于核对真实入口、导航、安全区和已工作的交互。
3. BG Stats 用于参考对局记录、统计维度和从汇总进入明细的能力；这些能力使用龙城现有视觉体系表达。
4. 附件中标为“探索”“变体”的书架、扇形、拼贴等页面保留为备选，不同时混入正式页面。录入方案 1A 只借鉴搜索、候选、详情、确认的步骤组织，视觉以正式组件为准。

## 各桌游页面的具体安排

### 游戏名称的统一展示

- 复用 `miniprogram/templates/boardgame-name.wxml`：已核对的中文名作主标题，BGG 原名作副标题。优先采用已核对的 BG Stats 中文名；缺少中文名时显示原名。原名与主标题相同或缺失时不重复显示。
- 副标题统一使用次级文字色 `#4B5563`，字号 12px、行高 18px。双列馆藏卡主、副标题分别单行省略，并预留一致的标题区高度；详情、历史、排行、活动游戏行和选择抽屉允许换行，长英文单词不能撑出容器。
- 当前游戏资料和历史快照分开：历史及计分表标题优先展示当前名称，记录当时的快照仍保留。搜索同时接受中文、英文和已保存别名。
- 桌游资料中已有可靠中文时优先展示中文：中文介绍经核对后存为本地 `description` 覆盖，原文保留在 BGG 来源中；录入候选也复用已核对的名称与介绍。语言和常见版次术语使用统一中文标签，保留出版商、年份和源版次 ID。编辑输入仍使用原始版次字段，不能因界面翻译触发重新绑定。
- 不将仅“含汉字”的日语介绍、版本或别名自动当成中文。没有中文资料时保留原文；分类和机制词典、AI 翻译仍按后续阶段处理。

### 桌游封面的统一展示

- 桌游封面、版次图和列表缩略图统一使用 `aspectFill`：短边撑满图片区域，保持原始比例，长边超出时居中裁切。适用于桌游库、游戏详情、录入候选与版本、活动提名、统计和管理页面。
- 沿用既有图片容器尺寸、圆角与占位状态，不拉伸原图，不修改原始图片文件或来源地址。操作图标继续完整展示，不套用照片裁切规则。

### 桌游库与录入

- 从“工具 → 桌游库”进入二级页面，使用现有返回导航；标题采用“桌游库”。龙城水印沿用现有背景层的克制用法，不铺在封面、筛选文字或密集表格上。
- 以搜索、筛选、馆藏卡为主。常用范围切换放在列表上方，复杂条件进入统一筛选抽屉。录入作为清晰的主操作；历史、统计、我的馆藏归入次级入口区，避免首屏连续堆叠多排按钮。
- 使用正式双列卡片与现行卡片尺寸，优先展示封面、名称、人数、时长、实物可用情况。中文分类和机制展示继续遵循一期范围。
- 录入主流程按用户确认的“图片 / 名称 → BGG 搜索 → 展示候选资料 → 用户选择正确条目及版次 → 实物信息 → 保存”组织。图片识别只提供搜索词，本地已收录只提示重复；不能自动选中或跳过候选界面。名称输入不依赖视觉服务，未找到正确结果时保留手工录入后备路径。名称部分已实现，见 [实际接口与页面](../../backend/design/boardgame-library/14-name-intake.md)；图片输入见 [后续OCR方案](../../backend/design/boardgame-library/13-photo-recognition.md)。

### 游戏详情

- 沿用活动详情从主视觉到标题、状态、资料的层级，封面展示保证盒面主体可辨认。
- 按“游戏资料、馆藏与可用性、本体与扩展、游玩记录”分组；较长说明折叠，点击分组进入对应详情或抽屉。
- 收藏、想玩、登记库存等操作随用户权限和当前状态呈现，底部只保留本场景明确的主要操作，避免所有动作同等突出。

### 活动中的提名、计划与记录

- 活动详情沿用原有主视觉、标题和基本信息，再增加“这次玩什么”业务卡。当前代码已将入口移至基本信息卡之后。
- 业务卡展示提名与已玩情况的摘要，进入后按“大家想玩、游戏安排、实际对局”分组；多人提名通过头像预览和数量表达，点击打开统一名单抽屉。
- 活动开始前允许符合权限的人修改提名；已打卡参与者可记录对局。控件状态与服务端权限、活动时间一致。
- 活动报名、签到仍由活动原有操作栏承载；录局页面负责保存对局。游戏提名、计划和实际已玩记录保持各自状态，未实际记录的计划不显示为已玩。

### 记录对局与计分

- 参照活动表单按“本局信息、参与人、成绩”分组，活动上下文放在顶部。扩展模块、队伍、计时和更多选项按需要展开，减少首次录入的信息负担。
- 选人使用现有头像名单结构，成员来自小程序用户。每人一行显示昵称、成绩或状态；复杂计分表进入独立页面，沿用相同导航和底部操作栏。
- 空白、0 分、摆烂、没开完和掀桌使用明确文字标签，不能只靠颜色区分。摆烂保留参局且显示未获胜；分数、特殊状态和赢家选择继续遵循已确认规则。
- 输入错误显示在相关字段或滚动内容区，关闭、返回和保存沿用现有表单习惯；提交中防止重复操作，失败保留填写内容。

### 统计与排行

- 先选择“全体 / 我的”及活动、月份、季度、年度等范围，再看总览卡、趋势和榜单。复杂指标从相应卡片或分区进入明细，避免用长菜单承载全部首屏内容。
- “最想开”展示提名人次与活动场数，“开的最多”展示已确认的对局统计口径；点击数据进入对应活动或对局明细。
- 玩家榜沿用头像、名次和数值行；游戏榜使用封面代替头像。榜首强调、热力图和进度条按内容选用，普通详情和表单沿用中性背景。
- 排名、并列、样本数和可比较范围以接口结果为准，保留单款游戏与比赛方式限制；现有活动签到榜的计算逻辑不迁移到桌游榜。

## 实现与验收

已完成桌游代码共享样式迁移、入口与导航整理、活动内业务卡位置、录局表单分组、统计首页层级，以及用户头像和现有关闭图标的复用。一级抽屉的三档高度、标题区、内容视窗和固定操作栏已按规范实现；验证证据见 [本地报告](../../backend/design/boardgame-library/verification.md)。浏览器中的微信控件替代不能作为原生渲染验收。

页面调整后按以下标准逐项验收：

1. 同时摆放现有参照页和新桌游页，核对标题、导航、卡片、信息密度、图标、弹层和主要操作的延续关系。
2. 核对 390px 基准和 320px 窄屏下的长名称、长昵称、空态、加载、失败重试、多行标签、多人和复杂成绩；内容不重叠或裁切。
3. 验证返回路径、筛选保留、表单取消、输入错误、保存反馈与安全区；全局导航保持五项，演示用导航不进入正式页面。
4. 修改 `.pen` 后检查整个画布全部顶层节点及代表性页面；浏览器截图、微信开发者工具和真机的验证结论分别记录。

本文件是持续维护的设计参照，实际代码、接口和数据库交付范围见 [真实页面对照](../../backend/design/boardgame-library/10-mini-program-pages.md)。
